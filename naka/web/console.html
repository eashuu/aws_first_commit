Endpoint DLP

A local agent with a TLS-terminating proxy, inspecting paste, upload and prompt traffic at the laptop before it reaches the wire — including traffic to consumer AI tools that never touch your network.

Loading fleet…

Enrol a machine

Install the agent and trust its root CA

The proxy terminates TLS locally, so the machine has to trust the certificate it mints. This is a real root CA on a real machine — install it only where you intend to, and remove it when done.

>npm install && npm run setup-ca

Enrol it against this control plane

Enrolment needs the operator key and returns a device token, shown exactly once. The device then reports its decisions to AWS and appears in the fleet table above within seconds.

>node scripts/naka-enroll.js --control <url> --key <X-Naka-Key>

Point it at the shared policy bundle

The endpoint agent reads the same Cedar text as the cloud planes, so an exemption written once applies everywhere.

>naka-agent --policy <control-plane>/policy

Remove the CA when you are finished

Leaving a TLS-intercepting root CA installed on a machine you no longer control is a genuine risk. This is the uninstall.

>certutil -delstore "Root" "Naka Root CA"
What it inspects

Paste

Clipboard content entering a browser text field or a chat client. The overlay names the entity types it found before the paste completes.

Upload

Multipart bodies leaving the machine. Documents are handed to the same file pipeline as the cloud plane, including the Indic-script pass.

Prompt

Requests to consumer AI endpoints, which are exactly the egress path a network DLP appliance never sees because the laptop is at home.

File & Document DLP

Attachments, scans and photographs of identity documents. Tier 2 handles layout and standard entities; tier 3 is the multimodal pass that reads an Aadhaar card whose holder's name is printed in Devanagari.

Tiers union, they never subtract. A finding proved by a local checksum cannot be removed by a later model that disagrees. That ordering is why a slow or unavailable tier degrades coverage but can never silently clear a document.

Disclosure ledger

What each principal has learned about each subject, cumulatively. The set is grow-only and updated with an atomic DynamoDB ADD, so two concurrent calls cannot race each other past the budget.

Meters for the loaded session

Load a session on the Agent Egress view — or run a scenario — and its per-subject meters appear here and there.
Why grow-only. A ledger you can decrement is a ledger an attacker can decrement. The set only ever gains members; a subject's budget is spent for the lifetime of the session, and the only way to get a fresh budget is a genuinely new session with a new identifier.

Detector coverage

Probed live against this AWS account and cached for 60 seconds server-side, so this is a real answer about what is reachable right now — not a claim baked into the page.

Tiers

NOT_RUN is not FAIL, and neither is OK. A service this account is not entitled to use is reported as a neutral NOT_RUN rather than a red error, because the dangerous conflation is between "this tier ran and found nothing" and "this tier never ran". A blind spot wearing the clean state's clothes is the exact failure this product exists to prevent.

Policy

Cedar source for all three planes. Saves are ETag-guarded against lost updates and versioned on write; the next call picks up the new bundle with no redeploy.

Cedar bundle

Writes are authenticated, reads are not. The console is a single-tenant operator surface: PUT /policy requires the shared key, everything else is readable by anyone who can reach the Function URL. Multi-tenant authentication is not implemented and is named as a gap rather than implied to exist.
