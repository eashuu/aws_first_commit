Naka

An agent doesn't leak a database. It leaks one field at a time, across a dozen innocuous-looking tool calls. Naka authorizes every call with Cedar, scans what comes back, and charges each disclosed field against a running per-subject budget — so the tenth call knows what the first one already gave away.

Three questions, asked on every single tool call

Most guardrails ask the first one. The leak lives in the second and third.

Q1

May this call happen?

Cedar authorizes the tool invocation itself, before it runs. A denied call never executes, and still lands in the audit trail.

Q2

May this principal learn this field?

Every detected field is authorized separately, against the ledger of what this principal already learned about this subject. Denied fields become numbered placeholders.

Q3

May this value be restored?

Rehydrating a placeholder into an outbound argument is its own Cedar question, bound to the destination. Without it, the guardrail becomes the exfiltration channel.
